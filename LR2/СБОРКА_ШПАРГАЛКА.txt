ЛР2 — ШПАРГАЛКА ПО СБОРКЕ И ЗАПУСКУ
=====================================

В ЛР2 ДВЕ отдельные части: криптоядро (собирается на обычном компьютере за
секунды) и сам драйвер-фильтр (собирается и запускается только в тестовой
виртуальной машине, т.к. это код ядра Windows).


ЧАСТЬ 1. КРИПТОЯДРО (на этом компьютере, не в ВМ)
====================================================

ШАГ 0. Открыть PowerShell, перейти в папку:

cd C:\Users\boris\Downloads\Desktop\221-331_Mukhortov\LR2


ШАГ 1 (если просят с нуля):

Remove-Item -Recurse -Force build


ШАГ 2. Настройка:

cmake -S . -B build -G Ninja -DCMAKE_C_COMPILER=clang

Разбор:
  -S .                      — исходники в текущей папке
  -B build                  — результат настройки в подпапку build
  -G Ninja                  — сборщик Ninja
  -DCMAKE_C_COMPILER=clang  — здесь компилятор clang, а не g++ (другой, чем
                               в ЛР1 — это нормально, оба компилятора C/C++)


ШАГ 3. Сборка:

cmake --build build

Появятся в build\bin\:
  - crypto_selftest.exe  — самопроверка шифрования (6 тестов)
  - lab2_client.exe      — клиент для тестирования драйвера (write/show/demo)


ШАГ 4. Запуск самопроверки:

.\build\bin\crypto_selftest.exe

Должно быть: ALL TESTS PASSED (6 проверок, включая эталонный вектор FIPS-197).


ЧАСТЬ 2. ДРАЙВЕР (только в тестовой виртуальной машине!)
============================================================

Драйвер ядра нельзя собрать и запустить на обычном компьютере — он должен
быть подписан тестовой подписью и загружен в отдельной ОС, иначе можно
уронить реальную систему. Для этого нужна ВМ LR2-Win10 (Oracle VirtualBox).

ШАГ 1. Запустить ВМ "LR2-Win10" в VirtualBox, дождаться загрузки Windows.

ШАГ 2. Внутри ВМ открыть Командную строку ОТ ИМЕНИ АДМИНИСТРАТОРА
        (ПКМ по значку → "Запуск от имени администратора").

ШАГ 3. Проверить/загрузить драйвер:

fltmc filters

Если PassThrough нет в списке:

fltmc load PassThrough

Разбор: fltmc — утилита управления Filter Manager (диспетчер фильтров
файловой системы Windows), load — загрузить конкретный минифильтр по имени.

ШАГ 4. Записать и прочитать тестовый файл (доказать, что шифрование
работает прозрачно):

lab2_client.exe write C:\lr2test\test.lab2ext "Любой тестовый текст"
lab2_client.exe show C:\lr2test\test.lab2ext

Если драйвер загружен — увидишь тот же текст, что записал.

ШАГ 5 (доказательство реального шифрования на диске):

fltmc unload PassThrough
lab2_client.exe show C:\lr2test\test.lab2ext

Без драйвера на экран выведется мусор (шифротекст) — значит, на диске
данные реально зашифрованы, а не просто спрятаны. Потом загрузить обратно:

fltmc load PassThrough


ЕСЛИ ЧТО-ТО ПОШЛО НЕ ТАК
=========================

Ошибка "cmake не распознано"
  → см. PATH, как в шпаргалке ЛР1 (должен быть настроен один раз навсегда).

Файл lab2_client.exe в ВМ не найден (C:\lr2test\)
  → скопировать заново из общей папки:
    copy "\\VBOXSVR\LR2\build\bin\lab2_client.exe" "C:\lr2test\lab2_client.exe"

Окно .bat закрывается мгновенно при запуске двойным кликом
  → запускать не двойным кликом, а из уже открытой консоли администратора
    (набрать имя файла и Enter) — тогда окно останется открытым и будет
    видна реальная ошибка.

"Ошибка: Отказано в доступе" на fltmc unload
  → значит файл драйвера ещё занят ядром с прошлой загрузки. Перезагрузить ВМ.


ВОЗМОЖНЫЕ ВОПРОСЫ ПРО СБОРКУ
==============================

В: Почему для ЛР2 нужна виртуальная машина, а для ЛР1 — нет?
О: ЛР1 — обычная программа пользовательского уровня. ЛР2 — драйвер УРОВНЯ
   ЯДРА (встраивается в саму Windows, видит все файлы в системе). Ошибка в
   таком коде может уронить всю ОС, поэтому тестируют в одноразовой ВМ,
   а не на реальном компьютере.

В: Что такое PassThrough, что это за имя?
О: Имя службы драйвера-минифильтра, прописанное в driver\passthrough.inf —
   так Windows и утилита fltmc идентифицируют именно наш драйвер среди
   других (их в системе одновременно десятки).

В: Где настроено шифрование, какой алгоритм?
О: src\crypto_core.c — AES-256 (библиотека tiny-AES-c), доработан под режим
   "счётчик", чтобы шифровать блоки произвольного размера со смещением.
   Эта же логика используется и в самом драйвере (driver\passthrough.c),
   и в автономных тестах (crypto_selftest.exe) — один и тот же код.

В: Почему расширение файла именно .lab2ext?
О: Драйвер (driver\passthrough.c) фильтрует операции только для файлов с
   этим расширением — остальные файлы в системе не трогает. Расширение
   задано константой в коде, можно посмотреть и поменять там же.

В: Как доказать преподу, что шифрование настоящее, а не "для вида"?
О: Ровно шаг 5 выше — выгрузить фильтр и показать, что без него файл
   читается как бессмысленный набор байт, а не как исходный текст.
