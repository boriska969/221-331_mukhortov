ЛР3 — ШПАРГАЛКА ПО СБОРКЕ И ЗАПУСКУ
=====================================

Всё собирается и запускается на этом компьютере (виртуальная машина не
нужна — режим Simulation имитирует работу Intel SGX программно).


ШАГ 0. Открыть PowerShell, перейти в папку:

cd C:\Users\boris\Downloads\Desktop\221-331_Mukhortov\LR3


ШАГ 1 (если просят с нуля):

Remove-Item -Recurse -Force build


ШАГ 2. Одна команда — собирает ВСЁ (и анклав, и клиент):

.\build.ps1 -SdkPath C:\Users\boris\Downloads\Intel_SGX_SDK_for_Windows\nuget_extracted\build\native

Разбор:
  build.ps1    — наш скрипт, сам вызывает MSBuild для обоих проектов
                 (Enclave и app) и подписывает анклав (sgx_sign)
  -SdkPath     — где лежит распакованный Intel SGX SDK (include- и
                 bin-файлы для сборки и подписи анклава)

Если выскочит ошибка "выполнение сценариев отключено" — один раз перед
этим выполнить:

Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass


ШАГ 3. Появятся в build\bin\:
  - table_app.exe        — этап 1, без анклава (для сравнения)
  - app.exe               — клиент, обращается к анклаву
  - Enclave.signed.dll    — сам анклав (подписанный)
  - несколько sgx_*.dll   — библиотеки симулятора SGX (скопированы сами)


ШАГ 4. Запуск:

.\build\bin\app.exe 3
.\build\bin\app.exe 5
.\build\bin\app.exe abc

Ожидается:
  app.exe 3   → "row 3: j.petrova;Hd5*nRt2%Woq" (реальная запись из анклава)
  app.exe 5   → WARNING (номера 5 в таблице нет, там только 0-4)
  app.exe abc → WARNING (не число)


ШАГ 5. Полная автоматическая проверка (30 тестов + анализ бинарников):

.\verify.ps1

В конце должно быть:
  PASS: 30/30 runtime checks
  PASS: plaintext is present in table_app.exe and Enclave.signed.dll; absent from app.exe


ШАГ 6. Посмотреть анализ "в открытую ли хранятся данные":

notepad analysis\logs\binary_strings.txt

В app.exe — все записи "NOT FOUND" (скрыты внутри анклава).
В Enclave.signed.dll — записи НАЙДЕНЫ со смещениями (это важно объяснить
преподу честно, см. вопросы ниже).


ЕСЛИ ЧТО-ТО ПОШЛО НЕ ТАК
=========================

Ошибка про "выполнение сценариев отключено" (PSSecurityException)
  → см. команду Set-ExecutionPolicy выше, выполнить перед build.ps1.

Сборка падает на этапе подписи анклава / "Enclave_private.pem не найден"
  → ключ подписи генерируется автоматически при первой сборке, он не должен
    храниться в репозитории. Если файла нет и сборка падает — просто
    запустить build.ps1 ещё раз.

app.exe не находит Enclave.signed.dll
  → они должны лежать РЯДОМ, в одной папке build\bin\. Не копировать
    app.exe отдельно от остальных файлов этой папки.


ВОЗМОЖНЫЕ ВОПРОСЫ ПРО СБОРКУ
==============================

В: Почему для ЛР3 не нужна виртуальная машина, как для ЛР2?
О: Используется режим Simulation — он программно имитирует работу SGX
   без реального защищённого железа. Для настоящего аппаратного SGX
   нужен отдельный процессор с его поддержкой, которого на обычных
   компьютерах обычно нет.

В: Где конфигурация сборки, что такое build.ps1?
О: Это наш собственный PowerShell-скрипт (не часть SDK), он вызывает
   MSBuild для двух файлов проекта — Enclave\Enclave.vcxproj (анклав) и
   app\app.vcxproj (клиент), используя пути и команды, которые обычно
   генерирует мастер Visual Studio. Можно открыть и прочитать — там видно
   каждую вызываемую команду (sgx_edger8r для генерации кода интерфейса,
   sgx_sign для подписи).

В: Что такое ECALL, где он объявлен?
О: Единственная функция, которую анклав разрешает вызывать снаружи —
   ecall_get_row. Объявлена в Enclave\Enclave.edl (специальный файл-
   интерфейс анклава), реализована в enclave\enclave.c.

В: Данные в DLL анклава видны в открытую — это не провал?
О: Нет, это задокументированная особенность: sgx_sign подписывает код для
   подтверждения подлинности (аттестации), но НЕ шифрует сам файл. Реальная
   защита данных в памяти работает только на настоящем SGX-железе, и это
   прямо прописано в README.md и в ответах на вопросы защиты
   (theory_answers.md, вопрос про хранение данных в production).

В: Почему два разных .exe — table_app.exe и app.exe?
О: table_app.exe — версия БЕЗ анклава (этап 1, для сравнения, видно что
   данные там читаются в открытую). app.exe — финальная версия, данные
   внутри анклава. Сравнение их двоих и показывает, что защита реально
   работает.
