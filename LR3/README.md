# ЛР3 - защита на аппаратном уровне: доверенная среда выполнения (Intel SGX)

Задача: вынести таблицу учётных записей в анклав Intel SGX и получать строки только через
ECALL-функцию. Структура по этапам методички.

## Статус

| Этап | Файлы | Статус |
|---|---|---|
| 1. Незащищённое приложение | `stage1/table_app.c` | собрано и проверено (строка 0, 3, неверный номер, нечисловой ввод) |
| 2. Анклав | `enclave/Enclave.edl`, `enclave/enclave.c` | код написан, **не собран**: нужен Intel SGX SDK и Visual Studio 2019 |
| 3. Интеграция в клиент | `app/app.c` | код написан, **не собран** (нужен сгенерированный `Enclave_u.h`) |

## Что нужно для сборки этапов 2-3 (делает студент)

1. Visual Studio 2019 Community (методичка: VS 2022 не поддерживает инструменты SGX).
2. Intel SGX SDK for Windows: регистрация аккаунта Intel и запрос на доступ с указанием учебной цели.
   Загрузка возможна только после письма о подтверждении, поэтому этот шаг сделать заранее.
3. Подключить плагины `SEConfigureVS2019.vsix` и `SEWizardVS2019.vsix` из каталога SDK.
4. Сборка в конфигурации Simulation / x64; при отсутствии RSA-ключа сгенерировать его (см. ниже).

## Ключ подписи анклава

Приватный ключ `enclave_private.pem` нельзя хранить в репозитории (он в `.gitignore`).
Генерация (OpenSSL из MSYS2 или Git for Windows):

```
openssl genrsa -3 -out enclave_private.pem 3072
```

## Проверка результата

После сборки проверить, что строки таблицы не видны в `Enclave.signed.dll` в открытом виде
(hex-редактор с колонкой адресов). Ответы на вопросы к защите - в отчёте.
