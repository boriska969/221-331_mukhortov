ЛР1 — ШПАРГАЛКА ПО СБОРКЕ С НУЛЯ
=================================

Если препод попросил удалить папку build и собрать заново — делай по порядку,
ничего больше не нужно (PATH уже настроен навсегда, DLL копируются сами).


ШАГ 0. Открыть PowerShell, перейти в папку проекта:

cd C:\Users\boris\Downloads\Desktop\221-331_Mukhortov\LR1


ШАГ 1 (если просят показать "с нуля" — удалить старую сборку):

Remove-Item -Recurse -Force build

Что это: просто стирает папку build со всеми старыми файлами. Исходный код
(.cpp/.hpp) не трогает — он лежит отдельно и никуда не девается.


ШАГ 2. Настройка (configure) — CMake готовит инструкции для компилятора:

cmake -S . -B build -G Ninja -DCMAKE_CXX_COMPILER=C:/Users/boris/tools/msys64/ucrt64/bin/g++.exe -DLR1_DEPS_ROOT=C:/Users/boris/tools/msys64/ucrt64

Разбор:
  cmake              — программа-настройщик сборки
  -S .               — исходники в текущей папке
  -B build           — результат настройки класть в подпапку build (создастся сама)
  -G Ninja           — какой сборщик использовать
  -DCMAKE_CXX_COMPILER=...  — какой компилятор (полный путь, чтобы не перепутать
                               с другим g++, который тоже есть в системе)
  -DLR1_DEPS_ROOT=...       — где лежат OpenSSL и nlohmann/json (библиотеки проекта)

После этой команды exe ЕЩЁ НЕ появились — только подготовка.


ШАГ 3. Сама сборка — вот тут реально компилируется код:

cmake --build build

Появятся все три программы в C:\Users\boris\Downloads\Desktop\221-331_Mukhortov\LR1\build\bin\:
  - PassManager.exe     — менеджер паролей (GUI)
  - Protector.exe       — протектор для самоотладки
  - CredentialTool.exe  — утилита создания/проверки файла с паролями

Библиотеки (libcrypto-3-x64.dll, libstdc++-6.dll, libgcc_s_seh-1.dll,
libwinpthread-1.dll) и credentials.bin скопируются туда же АВТОМАТИЧЕСКИ.


ШАГ 4. Запуск и проверка:

cd build\bin
.\PassManager.exe

Пин для входа: 1234


ЕСЛИ ЧТО-ТО ПОШЛО НЕ ТАК
=========================

Ошибка "cmake не распознано"
  → значит открыл СОВСЕМ новое окно, в котором ещё не подхватился PATH.
    Переоткрой PowerShell (закрыть и открыть заново) — должно появиться.
    Проверка: cmake --version

Ошибка "Permission denied" / "cannot open output file ...exe"
  → PassManager.exe или другой exe сейчас ЗАПУЩЕН, Windows не даёт его
    перезаписать. Закрой открытое окно программы и собери заново.

Ошибка про LR1_DEPS_ROOT ("Укажите каталог зависимостей")
  → забыл флаг -DLR1_DEPS_ROOT=... в команде шага 2, или перепутал путь.

Если PassManager.exe не запускается без видимой ошибки (мигнул и закрылся)
  → не хватает DLL. Проверь, что в build\bin есть все 4 библиотеки
    (см. список в шаге 3). Если нет — наша CMakeLists.txt их больше не теряет,
    просто пересобери (шаг 3 ещё раз).


ДВА МЕТОДА ЗАЩИТЫ ОТ ОТЛАДКИ (если спросят показать оба)
===========================================================

Сейчас собран вариант БЕЗ проверки IsDebuggerPresent (метод через протектор).
Чтобы собрать вариант С этой проверкой — отдельная папка сборки:

cmake -S . -B build_debugcheck -G Ninja -DCMAKE_CXX_COMPILER=C:/Users/boris/tools/msys64/ucrt64/bin/g++.exe -DLR1_DEPS_ROOT=C:/Users/boris/tools/msys64/ucrt64 -DLR1_CHECK_IS_DEBUGGER_PRESENT=ON
cmake --build build_debugcheck --target PassManager

Этот PassManager.exe при запуске под отладчиком сам покажет предупреждение
(IsDebuggerPresent() == true). Обычный вариант (из build\) вместо этого
полагается на Protector.exe, который сам подключается первым и блокирует
посторонний отладчик.
